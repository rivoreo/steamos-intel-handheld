# Refine

把用戶原始意圖整理成足以決策與驗收的任務書，不把規格化變成每個工程任務
前的強制等待。

## 做法

保留用戶原話的核心意圖，按需要補上：

- 目標與使用者可見結果；
- 可判定的驗收標準；
- 本次範圍與明確不做；
- 已知約束、假設與需要查證的未知；
- 建議的驗證層級。

只保留有資訊量的段落，不強迫固定模板。

若缺失資訊會實質改變產品方向、資料模型、外部副作用或不可逆決策，集中提出
最少的問題。否則標示合理假設並直接交付任務書。只有用戶要求「確認後再做」
或 spec-only 時才停在規格；若用戶同時要求整理並實作，規格完成後可繼續。

不要把一般清楚任務擴寫成長篇 prompt，也不要因缺少形式化驗收句就阻擋模型的
合理自主性。
